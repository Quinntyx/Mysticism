# Physical spirit terrain handoff

Scope: only the new `dimension/spiritworld/terrain` package, its main-based test, and this handoff. No initializers, client, networking, components, core geometry, build configuration, sibling worktrees, dev or main changed.

## Parent integration (required)

1. Call `SpiritTerrainService.init()` from the common initializer, alongside extraction/activity initialization. It registers server tick, dimension change, respawn, disconnect, world unload, shutdown, block-break and block-use events. No manifest/mixin/resource changes are needed for terrain.
2. In the existing enter command, immediately **before** its dimension teleport, call `SpiritTerrainService.prepareEnter(player)` and abort on `false`. On a cancelled/throwing transition call `cancelEnter(player)`. Use an initial destination near the fixed realm origin `(0,128,0)` so ordinary player-loaded chunks cover the landing search. This package never requests chunk generation/tickets.
3. Prepared entry records the source return pose, temporarily suspends gravity, builds loaded collision, verifies personally selected observed two-block air, an unchanged owned full floor and actual body clearance, then lands once. Existing-floor discovery is independent of mutation eligibility or stamp epochs; it does not promise a complete 24-block halo. It restores gravity on landing/leave; timeout (400 ticks), pending disconnect and shutdown return to the source pose when that source world still exists. Ordinary movement/login/reload never reanchors or lands again. Unprepared external dimension teleports cannot safely suspend gravity and produce a visible warning; they are not a supported entry path.
4. Traversal uses `support(ServerPlayerEntity) -> Optional<Support>`. The nested public record has the agreed `(String landmarkId, Vec384f embedding, Vec3d center, Vec3d normal)` signature. `center` is the **frozen realm anchor** of the owning source landmark, not a camera-relative/block/chunk center. Normal is actual horizontal floor contact's up normal; embedding is defensively copied on construction/access. The lookup checks current generated block ownership, actual collision contact, grounded state and pinned profile; at most 18 footprint cells and 32 shape boxes per cell, with no catalog/page/model IO.
5. Terrain calls the sibling implementations' actual `LandmarkProfiles.current/wrap` and `SpiritActivityService.effectiveEmbedding/importance`. The merged wave-1 authoritative repository is named **`LandmarkStore`**, not the parallel message's `LandmarkSavedState`; no placeholder/second landmark repository was invented.

## Production behavior and limits

* The real adapter uses the spirit `ServerWorld` only; FULL chunk lookup passes `create=false`. Blocks use `setBlockState(NOTIFY_LISTENERS | FORCE_STATE | SKIP_DROPS)` on the server thread, providing ordinary Minecraft collision, client block updates and occlusion. No source-world chunk/geometry scans, model calls or inference run on ticks.
* Metadata selection consumes **all** results of repository semantic range, radius 1.25, then the scoped frozen-placement adaptation of the foundation clustering/distortion/crowding selector (cluster radius .18), bounded effective importance, retained representative seed slots and hysteresis. A catalog/result overflow fails visibly rather than becoming nearest-K truncation. Metadata refresh is one player per 20 ticks, with a 100-tick minimum per player.
* First use freezes the profile, orthonormalized initial basis, world seed, semantic origin, realm origin `(0,128,0)` and scale 96. Per-source-ID placements also persist and never move when camera, activity or subsequent base metadata changes. Source offsets retain their directions at unit scale. Realm manifest key: `mysticism.spirit_terrain.v1`, in the spirit dimension's PersistentStateManager.
* Shared occupancy is the conservative union of observed solids: one landmark's air/unknown never erases another floor. A deterministic absolute-coordinate dither chooses actual palette material/owner with bounded importance and a shared seven-probe smoothing halo. Observed air corridors are not filled with invented smoothing solids.
* Opaque fog: 64 blocks (visible 48). Ordinary mutation/cleanup requires region AABB distance **greater than 96** from every player; prefetch/culling is 160. Prepared entry is the explicit bootstrap exception, still excluding player-intersecting regions. Fully fog-hidden replacement needs no visible collision animation. There is no new shader-side per-slot alpha protocol.
* Global bounds: eight spirit players/layers, 256 catalog scans and frozen placements, two pages/landmark, conservative 65536 leaves/landmark, palette cache 512 states, frontier 4096 regions, 128 owned regions/65536 ledger cells. A geometry cursor advances one page/1024 leaves per tick, then queues 64 projected regions per tick. One 8³ region preflight/write batch per tick; up to 16 frontier eligibility probes. Ordinary writes <=512/tick; failed writes can additionally attempt <=512 rollback writes.
* Only initial air cells are overlaid; existing base terrain/block entities are not excavated. Cleanup compare-restores original air only while current blocks still equal generated blocks. Broken/changed cells and same-state player interactions become protected, persist and continue consuming bounded capacity. No unsafe eviction of those edits.
* Publication stages geometry/frontiers before activating a field; region ownership publishes only after successful writes. Cold page loading uses the foundation incremental cursor. Palette resolution is server-thread registry work; invalid materials, profiles, excessive pages/frontiers/catalog or busy cursors produce visible status and retain existing collision.

First metadata use freezes the source-base placement; later geometry staging uses that same persistent transform. ## Remaining limitations / review targets

* Only already-loaded FULL realm chunks are stamped. If no selected geometry has an accessible loaded safe landing, prepared entry times out and returns; terrain does not silently force-load it. Base solids can obstruct an observed source air corridor, and are intentionally preserved.
* Large (>2-page), overlapping page-AABB masks, fluids, block-entity solids and excessively complex (>32 collision boxes) support shapes are conservatively unsupported. Partition/reconcile upstream rather than silently dropping source pages or synthesizing stone. Native vanilla block physics can detach a generated block as an edit.
* Resource caps fail closed; protected player edits can exhaust region capacity. There is no disk compactor, topology migration or ownership-aware player-edit eviction. Representative selection history is session-local, while actual transforms/overlay ownership are persistent.
* Smoothing changes boundary **material weights**, not topology; it does not manufacture a watertight bridge across genuine unknown/observed geometry gaps. Stable near-player collision is kept instead of locally rebuilding a changing representative.
* Vanilla chunk and PersistentState saves are not one crash-atomic transaction. The pending entry return pose/gravity reservation is session-local: an abrupt process crash during suspended-gravity entry is not recovered as a persisted entry transaction. Normal disconnect/shutdown cleanup is wired but not exercised with a booted server in these checks.
* Initial frozen mapping depends on the first valid player's current profile/basis. Profile changes fail closed and require explicit migration; they never silently reproject an existing realm. Ensure extraction and traversal initialize a valid current unit embedding before permitting entry.
* Actual world/dimension/player event behavior, collision synchronization, occlusion against the shader, chunk unload/reload ownership and multi-player frontier fairness still require parent integrated runtime review. The tests exercise production sampler/ledger/shape-contact/codecs, not a fabricated full Minecraft server.
